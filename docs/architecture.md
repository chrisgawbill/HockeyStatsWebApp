# HockeyStatsWebApp Architecture

NHL stats app: React (Vite) frontend + independently deployed HockeyStatsAPI Express service + Postgres (Neon) persistence + Python/Anthropic AI subprocess. The API source lives in the separate `HockeyStatsAPI` repository; this repository contains the frontend only.

## Core Rules & Invariants
- **Frontend Standard:** Bulletproof React. Features isolate their own `api/`, `components/`, `hooks/`, `types/`, `utils/`. Cross-feature imports forbidden (exceptions: `schedule` uses `game-detail` boxscore; `TeamPage` uses `schedule` game model; `TeamHero` renders `after-action-reports` `FavoriteTeamButton` and the shared header's `AccountCorner` renders its `NotificationBell`; `PlayerStatsDialog`, `PlayerStatsSection`, `ThreeStars`, `StatLeaderCard`, `StatsLeaderModal`, `PlayerStatsSelection` and `ScoringSummary` render `favorite-players` `PlayerHeadshot`/`FavoritePlayerStar` (`StatLeaderCard` also uses its `playerCardFormat` helpers), and `NotificationBell` reads `favorite-players` state to list Weekly Player Reports; `my-hockey` reads the `after-action-reports` and `favorite-players` contexts and renders `PlayerHeadshot`; other features import `ScheduledGame`-shaped helpers from `schedule/utils/gameStatusHelper.ts` rather than copying them; `matchup` reads the `schedule` games and `teams` `ListOfTeamsContext` contexts and renders `schedule` game models; `player-compare` renders `favorite-players` `PlayerHeadshot` and uses its `playerCardFormat` helpers). Shared primitives keyed on bare values (a `gameState` string, a date string) live in `react/src/lib/` instead — features import from `lib/` rather than copying a helper or reaching into another feature.
- **API Boundary:** The frontend calls the deployed API through `VITE_API_URL` and feature API modules. The API repository owns the Feghhi 3-Pattern backend, cache/database infrastructure, NHL clients, and AI subprocess. The design library has no API or network dependency.
- **Mapping Boundary:** Anti-corruption layer in `slices/<slice>/mappers/`. Raw NHL payloads cached first via `GetOrFetch`; mapping runs **after** cache read on outbound response. Never cache normalized contracts.
- **Imports:** Frontend uses `@/*` (`react/src/*`). Backend uses Node subpath imports with `.js` extensions: `#presentation/*`, `#slices/*`, `#platform/*`, `#composition/*`. No relative climbing (`../../`).
- **Game previews on /matchup (PREVIEW-01):** A game that has not started previews on `/matchup?teamA=<away>&teamB=<home>&game=<id>`. `lib/gamePath.ts` (`isPreviewGame`, `getGamePath`, `getMatchupPreviewPath`) decides: future/pregame **and** the scheduled start still ahead goes to the matchup page, anything else to `/game/:gameId`; the start-time check keeps a season list loaded before puck drop from sending a started game back. Schedule day cards and calendar chips, the team page schedule strip and the Up next rows (home strip and My Hockey) all link through it, so every game card is clickable (the ticket button stops propagation). `/game/:gameId` is wrapped by `app/GamePreviewRedirect`, which redirects (history replace, route state kept) from the loaded season list; `GameDetailPage` repeats the check on its box score for games the list lacks. Both `<Navigate>`s are keyed on `location.key` because the season provider can replace a bare URL with its `?season=` copy right after the redirect fires. `matchup/utils/matchupGameContext.ts` parses `game=` and accepts it only for a season game between the two selected teams; changing a team drops it. The preview header shows away at home, date, arena and a puck-drop chip (`PuckDropStatus`) that a local timer (`hooks/useHasTimePassed`, no network) turns into a link to the game page at the scheduled start. The page reads only the loaded season games and league team list and never polls. Every matchup (preview or not) shows a `TeamDna` card per team (`MatchupTeamDna`, ranked from the league list, tinted with `lib/teamColor` `getTeamAccentColor`): side by side from 768px, one at a time behind a team switch (`SlidingToggle`, also swipeable) on phones; hidden while the list loads, on error, or with no season data. Order: series summary, Team DNA, form, played, upcoming. Shared pieces: `components/TeamDna` (optional `title` and `teamColor`; without a color it inherits `--color-primary`, which the team page sets) and `components/FormStrip`, each with its own CSS module; their pure helpers live in `lib/teamDna.ts`, `lib/teamForm.ts` and `lib/teamColor.ts` with structural input types, so `lib/` imports no feature types.
- **Favorite players and Weekly Player Report (WPR-01):** `features/favorite-players` owns favorite players (max 10) and the Monday report. `PlayerHeadshot` is the reusable headshot with a corner `FavoritePlayerStar` button (own button, so tapping the photo keeps the host's behaviour; signed-out and limit messages show as a fixed toast; hidden when the API predates favorite players, i.e. `GET /api/favorite-players` 404s). `FavoritePlayersProvider` (mounted in `index.tsx` beside `AfterActionReportsProvider`) loads favorites, the reports (`/api/weekly-player-reports`) and the one push switch (`/api/push/weekly-report`) on sign-in, on refocus, and every 15 minutes. The bell inbox merges weekly reports with After Action Reports by time and sums both unread counts; the switch sits under the phone-notification controls. `/weekly-report[/:weekStart]` renders the frozen report (opening marks it read) and the favorites list with unstar buttons. Weekly pushes carry `kind: "weekly-report"`; `sw.js` posts the read token and opens `#/weekly-report/<weekStart>` (`wpr-navigate` / `wpr-report-read` messages). The API (HockeyStatsAPI, API-WPR-01) builds reports Monday ~9:00 ET for the previous Monday–Sunday ET week and skips league-break weeks. STAR-01 put the starred headshot on leaderboard dialog and scoring-summary rows and a bare `FavoritePlayerStar` before box-score names (no photos there); the leaderboard dialog hides its Pos column at ≤576px so names fit. `lib/playerHeadshot.ts` holds the NHL default-mug URL the player lists fall back to. The landing page's stat leaders (HOME-LEAD-01) render `StatLeaderCard` as a stat variant of the shared `FavoriteCard` (category, big value, name, TEAM · POS; the star is its own button, the card body opens `StatsLeaderModal`): phones get one "Stat leaders" section with a Skaters / Goalies switch over a 2×2 grid, which a horizontal swipe also switches (`lib/useHorizontalSwipe`), from 768px both groups show under their own headings (`StatLeadersSection`, `lib/useMediaQuery`). The landing page renders `FavoritePlayersRow` (HOME-FAV-01) right under its intro header: the signed-in user's favorites as headshot cards linking to `/team/<tri>`, hidden when signed out or when the API predates favorite players.
- **My Hockey (FEED-01):** `features/my-hockey` owns `/my-hockey` (Up next, Last results, Your players; signed-out prompt) and the home `UpNextStrip` (first 3 games; signed out, its heading with a sign-in line and the Google button; rendered by `LandingPage`: under the favorites rows on phones and tablets, a 24rem right-hand column beside them from 1001px, where the rows scroll sideways; "See all" on "Your teams" and the avatar menu link to the page). Its own `api/` reads `/team/schedule/:triCode` (one per favorite team and favorite player's team; the API caches it 12 hours), `/schedule/:gameId` box scores for games that have started but are not final there and for each player team's latest game, and the per-team skater/goalie summaries; identical requests within a minute are shared so home → page reuses them. Pure selection (`utils/feedSelection.ts`: next/last game, live first then start time, newest final first, a shared game once from the higher-tier favorite) and formatting (`utils/feedFormat.ts`) are unit tested. Refreshes on refocus and every 5 minutes while visible. A failed team schedule hides only that team. Favorite teams are capped at 5 by the API (409 → `FavoriteTeamLimitError`, message on the team-page star). `lib/teamLogo.ts` builds the themed NHL logo URL, rendered by `components/TeamLogo`. Feed rows live in their own files (`UpNextRow`, `LastResultRow`, `FeedPlayerRow`, `FeedSection`, `FeedList`) and use the shared `FanCategoryBadge` (also on `FavoriteCard`), `SectionHeading` (home rows, stat leaders, the strip) and `PageIntro` (also the Weekly Player Report).
- **Fan categories (FAN-01):** Each favorite team and player carries a display-only `tier` (`diehard` | `fan` | `curious`, default `fan`) and an optional `label` (max 24 graphemes), edited with `PATCH /api/favorites/:triCode` and `/api/favorite-players/:playerId` (`updateTeamCategory` / `updatePlayerCategory`, optimistic with rollback). API modules default a missing `tier`/`label`, so an older API still works. Shared presentation lives outside the features: `lib/favoriteCategory.ts` (tiers, badge text, tier sort, grapheme count), `components/FavoriteCategoryMenu.tsx` (portal popover opened by the starred `FavoriteTeamButton` / `FavoritePlayerStar`), and `components/FavoriteRowSection.tsx` + `FavoriteCard.tsx` (vertical home cards, picture straddling the top border). `after-action-reports/FavoriteTeamsRow` ("Your teams") and `favorite-players/FavoritePlayersRow` feed those and are composed by `app/LandingPage.tsx`; both sort Diehard, Fan, Curious.
- **Player comparison (COMPARE-01):** `features/player-compare` owns `/compare?players=<id>,<id>[,<id>]` (plus the app's `season=`), two or three skaters or goalies side by side. `lib/comparePath.ts` is the URL contract (`parseComparePlayerIds`: drops non-numeric/non-positive and repeated ids, max 3; `getComparePath`), shared with the entry point, a "Compare" link beside Close in `teams` `PlayerStatsDialog` (reached from roster rows and favorite player cards), so neither feature imports the other. The page makes two calls, the league-wide `/player/skater/summary` and `/player/goalie/summary` (every player since API-COMPARE-01, with `teamTriCodes`, `shots`, `shootingPct`), which feed both the picker and the table. `utils/compareSlots.ts` turns the URL ids into columns: the first found player sets the group, an id with no season line gets an `unknown` slot and a player from the other group an `otherGroup` slot, each with Remove; picking or removing replaces `players=` (no history entry). `PlayerPicker` is an ARIA combobox over `utils/playerSearch.ts` (2+ letters, accent-insensitive word prefixes, last-name matches first, then games played, 8 results, picked players excluded). `CompareTable` renders `utils/compareStats.ts` rows (skaters GP, G, A, P, PPG = points per game, +/-, SOG, S%, TOI/GP; goalies GP, W, GAA, SV%, SO); `utils/bestValue.ts` marks each row's best (GAA lower, GP never, every tied leader, values compared at displayed rounding, all-tied rows and missing values unmarked). The stat-label column is sticky and a third player scrolls inside the table (`overflow-x: auto`, positioned so hidden "(best)" text is clipped there), never the page. Headshots use `lib/playerHeadshot.ts` `getSeasonHeadshotUrl` with the last listed team; the roster-dialog formatters (`formatSavePct`, `formatGaa`, `formatPlusMinus`, `formatMinutesSeconds`) live in `lib/statFormat.ts`.
- **Board game exception:** `features/board-game` (Rink Quest, see `docs/board-game-design.md`) is a self-contained game with no cross-feature imports. It additionally uses `engine/` (pure rules, no React), `ai/` (pure CPU policy), and `data/` (constant tables). Import direction: `components → hooks → ai → engine → data → types`. Its randomness is seeded via `engine/rng.ts`; state changes only through `gameReducer`. One narrow carve-out: `features/board-game/api/streakSync.ts` (driven by `hooks/useStreakSignInSync.ts` and `useBoardGame`) may call the network, for the optional Google sign-in streak backup/sync only, and only for a user who has signed in. `engine/`, `ai/`, `data/`, and the rest of `hooks/`/`components/` still make zero network calls.
- **Site-wide Google account (Product Owner approved):** Sign-in is optional and shared by every page. `lib/auth/AuthContext.tsx` (`AuthProvider`/`useAuth`, mounted in `app/index.tsx`) owns the app session token; `lib/auth/authApi.ts` exchanges Google Identity Services credentials for it. Discord sign-in (API-AUTH-02) is OAuth code plus PKCE in `lib/auth/discordAuth.ts`: `useAuth().signInWithDiscord()` keeps the state and verifier in sessionStorage (every access guarded) and leaves for Discord; on return to the app root `AuthProvider` removes `code`/`state` from the URL, checks the state, and posts `/api/auth/discord`; a cancel, deny or mismatched state leaves the user signed out. The global header (`components/AccountCorner.tsx`) shows `SignInIconButton` when signed out (SIGNIN-01: the bell's glass circle with a person figure, opening `SignInDialog` with Google and Discord; `lib/auth/signInProviders.ts` hides a provider whose `VITE_*_CLIENT_ID` was not set at build time) and the After Action Report bell plus avatar menu when signed in. The home Up next strip's signed-out prompt uses `components/SignInButton.tsx` (a "Sign in" text button opening the same `SignInDialog`); Rink Quest's pre-game screen opens `SignInDialog` from a pixel-style `GameButton` "Sign in". `GoogleSignInButton` is used only inside the dialog. Features react to `useAuth().token` for their own sync; nothing else stores credentials. `useAuth().isRestoring` is true while a saved token is being checked on load, so signed-out prompts (the home Up next strip's sign-in line) do not flash for returning users. Service worker access goes through `lib/serviceWorker.ts` `getServiceWorkerContainer()`: Firefox private windows keep `navigator.serviceWorker` but set it to undefined, and the root favorites providers crashed the whole app on it.
- **After Action Reports:** `features/after-action-reports` lets a signed-in user favorite teams (team page star) and keeps an inbox of reports, one per completed game a favorite plays from the time it was favorited (a game that started up to 12 hours earlier still counts). The API computes reports on request from cached schedules (the hosted API sleeps, so nothing runs on an in-process timer); the frontend refreshes every 5 minutes while a tab is visible and on refocus. Opening a report (inbox row or browser alert) marks it read and routes to `/game/:gameId`. Browser alerts use the Notification API only while a tab is open, require an explicit opt-in click, and alert each game once per browser. Phone push (AAR-02): the site is an installable PWA (`public/manifest.json`, generated HS icons in `public/icons/` via `react/scripts/generate-icons.mjs`) with a hand-written `public/sw.js` (push + notification click only, no fetch/offline caching) registered at `BASE_URL + sw.js?api=<API origin>` with scope `BASE_URL`. `hooks/usePushNotifications.ts` + `utils/pushNotifications.ts` read `GET /api/push/config`, derive on/off/denied/iOS-install-hint state from the device's real `PushSubscription`, and subscribe/unsubscribe via `/api/push/subscriptions`; sign-out deletes this device's subscription. The bell inbox hosts the opt-in and per-team mute (`PUT /api/favorites/:triCode/push-mute`); with push on, tab-only browser alerts are suppressed. Tapping a notification posts its read token to `/api/push/read`, focuses or opens `#/game/<gameId>`, and tells open tabs to refresh the inbox. Push timing (Product Owner): a GitHub Actions cron in HockeyStatsAPI runs every 10 minutes 16:00–08:59 UTC, checks the NHL scoreboard, and calls the secured `POST /api/push/dispatch` only around live or recent finals, so a push lands ~10–25 minutes after the final horn. Each report pushes once per user (a sent ledger seeded at opt-in, so nothing old is pushed); all-muted games are recorded without sending; no quiet hours.
- **Install banner (Product Owner approved):** `features/install-prompt` shows a mobile-only (≤576px) floating card above the bottom nav: "Install Hockey Stats · Get final-score alerts". Chromium gets **Install** (the `beforeinstallprompt` event captured early by `lib/installPrompt.ts`, imported from `app/index.tsx`); iOS gets **How?** → Share → Add to Home Screen steps. Never on the first visit: eligible from the second browser session or after opening a `/team/:id` or `/game/:id` page. ✕ / dismissed native prompt / "Got it" snooze 30 days; never shown when standalone or after `appinstalled`. State lives in `localStorage` `installPrompt.*` keys; while visible it sets `body[data-install-banner]` so `PageHeader.module.css` lifts (or, for the iOS steps card, hides) the search FAB. iOS/standalone detection is shared in `lib/displayMode.ts`.
- **Frontend tests:** Vitest (`cd react && pnpm test`), currently scoped to `src/features/board-game/**/*.test.ts`; ticket 2.13 widens the include.
- **Database/Writes:** Neon Postgres. Concurrency-1 task queue (`runServiceTask`) runs batched multi-row upserts (`batchUpsert`). Always upsert `seasons` row first (FK root).

```text
├── app/               # Root providers, HashRouter, App.tsx routes, LandingPage

└── styles/            # Global styling, tokens, reset
